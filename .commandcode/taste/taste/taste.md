# Taste
- Organizes coursework/projects as self-contained per-unit modules (`weekNN/`), each shipping its own data/corpus and importing no code from sibling modules (duplicate rather than share). Confidence: 0.6
- Holds every deliverable to a high quality bar: a runnable core module PLUS a pytest suite, a `verify.py` end-to-end checker, a Streamlit AppTest smoke test, and documentation — not just working demo code. Confidence: 0.65
- Maintains a root-level `GUIDE.md` documenting how to run and verify each module, and expects it kept accurate (e.g. test counts, file references must resolve). Confidence: 0.6
- Writes learning/design docs as markdown pages under a `docs/understanding/` folder, and expects the docs' cited file:line references and quoted numbers to be machine-checkable and kept true. Confidence: 0.55
- Python stack preference: Streamlit for web UIs, `rich` for console/terminal UIs, `pytest` for tests. Confidence: 0.6
- Prefers plain-English over jargon in UI copy and explanations; when an app has many features, wants a guided "Start here"-style entry point that walks through what to do, in order, and what should appear. Confidence: 0.6
- When asking about theory/concepts, wants them explained simply: strip a formal model down to its bare core (e.g. "just a set of pages plus a set of arrows"), anchor it with a tiny concrete example, and contrast competing options side by side (comparison table) instead of giving the full formal/mathematical treatment. Confidence: 0.5
- Wants web UIs to be self-explanatory — the app itself should make itself understandable through clear labels and good design, not by embedding instruction scripts/manuals ("how to" walkthrough text) or referencing the command line inside the UI. Confidence: 0.6
- Cares about UI/UX quality and visual polish ("best user experience", friendly design, "design it professionally"), and will invoke design-taste/design-skill guidance to enhance the interface. Means *visual/layout* design — cards, control placement, type scale, data tables as real UI — not merely reworded copy, and will push back if a "make it friendlier" change is only wording. Confidence: 0.65
- Learns and works hands-on: prefers to explore the running artifact first and then ask targeted follow-up questions, rather than being handed a full written reference up front. Confidence: 0.55
- Wants presentation/interview-ready (e.g. viva) prep material: "click → what you should see → the one line to say out loud", the numbers worth quoting, and a list of likely questions with one-line answers. Confidence: 0.5
- Expects interactive UI controls to actually work: clicking a "browse"/navigation button must land the user in the target view — a control that silently changes state while "nothing happens" on screen is a bug to fix, not acceptable. Confidence: 0.55
- Prefers a document/preview to open inline, directly beneath its own row via an explicit per-row "preview" button, rather than sending the user off to a separate tab/section. Confidence: 0.5
- Prefers breadcrumbs rendered as a single-line, chevron-separated, clickable trail with every ancestor crumb navigable (not a slash-joined static text line). Confidence: 0.45
- Prefers colour grounded in an established, professional design system with defined scale semantics (e.g. Radix Colors steps for subtle background / border / contrast-checked text) rather than invented/ad-hoc colours, assigning one hue per category with meaning. Confidence: 0.5
- In search UIs, wants matched query terms visibly highlighted in results (titles and previewed/highlighted body text) so users can immediately see *why* a result matched and scan for the words. Confidence: 0.5
- Expects *every* visible element to carry the app's colour system, including default framework chrome: data tables and action buttons must be coloured (accent-tinted headers, zebra rows, meters, filled primary buttons), never left grey/black-and-white, and is willing to replace framework widgets with custom HTML/CSS when the framework's defaults can't be themed. Confidence: 0.6
- Expects the UI to use real vector icons (e.g. Material Symbols) throughout — on buttons, stat/metric cards, inputs, and expanders — and flags their absence ("no icons") as a defect; wants iconography, not emoji or text-only controls. Confidence: 0.5
- Wants a hypertext/linking feature to be a *real, working use case*, not an abstract diagram: inline links rendered inside the document text (Wikipedia-style, `[text](url)`) that actually navigate on click to the target document, which itself carries further inline links — treating the graph model as prose made clickable. Confidence: 0.55
- Prefers a soft off-white (lightly warm/cream) page background with near-black body text and white card surface panels that lift off the base, rather than a stark pure-white-on-black or heavily saturated background. Confidence: 0.45
- When asking for guidance wants a single concrete recommendation (a committed plan, not just a menu of options), then delegates implementation with a terse go-ahead ("proceed") rather than restating requirements. Confidence: 0.5
- Prefers work to be additive/non-breaking: extend the existing structures and behaviour (same core model, existing feature lists, all existing tests still passing) rather than replacing or rewriting what already works. Confidence: 0.45
